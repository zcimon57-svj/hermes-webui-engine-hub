## 4. 推荐实现与状态权威

链路为：

`统一WebUI -> 用户身份/能力检查 -> 引擎/空间路由 -> ManagerClient -> 同引擎节点池 -> 独立Hermes状态 -> 报告/事件 -> 同一UI和原业务入口`

知识/Skill链为：

`允许的节点/工单反馈 -> 私有草稿 -> 所属引擎候选 -> 评测/审核 -> WeKnora远端正式资产与发布清单 -> 同引擎节点采用固定版本`

分工：

| 对象 | 权威/职责 |
|---|---|
| 用户身份、三类角色 | 服务端用户/身份服务，支持本地实名测试账号；已有SSO可适配。前端只显示能力，不作授权判定 |
| 引擎与空间 | 服务端目录：引擎、实例/项目、KB范围、Skill版本、可用节点；模型只能建议已授权候选 |
| 业务任务/Run/恢复/交付 | 一个现有Manager，通过版本化ManagerClient调用。不要在WebUI另造竞争调度权威 |
| 节点选择与运行协议 | 接收Manager给出的可信范围/Run身份，固定接收端、幂等键、状态scope与配置快照 |
| 正式知识/Skill | WeKnora远端为内容权威，单一版本发布权威；不要让UI本地副本和远端同时成为latest |
| Memory/会话/临时目录/学习草稿 | 活动节点/工单私有状态，有明确唯一写入者；原始私有经验不可自动扩大共享范围 |

内部Manager不可访问时：实现并记录`ManagerClient`合同（submit/query/cancel/events/recovery/report/delivery），以透明的本地reference做开发验收；可复用已有Paperclip作为本地参考路径或声明最小合同测试替身。替身只支持接口契约测试，真实WebUI/Hermes/WeKnora调用不能全mock。内部双版本/接口/投递验收继续F30 NOT_RUN，不把本地参考改称内部已上线，也不停止其它READY工作。

## 6. 角色与显示边界

以`permissions-v1.json`为本期具体合同：

| 角色 | 能力 | 不允许 |
|---|---|---|
| 管理员 Admin | 查看普通信息和脱敏扩展诊断；修改授权配置；问答；管理自己负责范围内的用户/运行 | 默认不显示明文密钥、不获得生产修复权限、不默认拥有知识发布权 |
| 只读 Viewer | 登录、浏览允许的会话/报告/已发布资产和概况 | 创建/回复问题、启动/取消Run、修改任何配置/资产/Memory/工作区；页面boot的自动建会话/保存也必须禁止 |
| 问答 Chat | 查看普通授权信息；创建问题、回复会话、取消自己的回答 | 修改配置、查看敏感/扩展诊断、发布全局知识/Skill、取消别人运行 |

管理员默认包含问答能力；Chat可取消自己的运行是建议默认，为停止长回答。知识草稿编辑/批准发布为单独capability，测试时显式授权，不等于增加第四类默认UI角色。

权限以动作/显示字段为主，不默认扩大成复杂企业多租户平台；仍须支持受限引擎/项目范围且不能通过Profile参数扩权。私有会话只在明确授权/共享后可读。所有列表、详情、下载、SSE/WebSocket、后台任务和自定义汇总走同一服务端检查。汇总中不得透露不可读节点/Run是否存在。

至少用三个独立测试账号和浏览器上下文验收。不要继续使用一个密码来宣称多用户。SSO/可信代理可接入，但直接客户端的身份/组/角色头不能被信任；Node管理密钥只在服务端，普通用户的UI角色不能提升MCP动作权限。

## 7. 节点部署与隔离

四引擎六节点沿用：MySQL node01、PG node03、Cassandra node02/05、Redis node04/06；可以扩展。引擎是逻辑空间，节点是运行位置，UI用户无需分别登录六个实例。

- 每个进程/节点独立可写Home、会话、Memory和工作区；同引擎正式只读资产可共享，不能共享活动数据库/Memory写入目录。
- 支持本机多进程以及配置远程Gateway；地址、凭据、健康、资产采用和状态API按节点绑定，UI集中访问。
- 默认新fork实验端口建议158xx，容器/网络/卷以本轮新项目前缀登记；若冲突选其它空闲端口并记录。不复用旧实验PID/卷/账号来制造复现。
- 逐节点配额、请求队列/并发和工具超时有边界。跨物理机故障/HA和不可信Issue任意代码强隔离须独立实测；没有环境就明确NOT_RUN，不用本机六进程外推。
- 远端Memory/文件/Skill管理优先使用稳定已有API；缺失时可在fork中提供部署于单节点的受限伴随服务。仅该节点/状态scope挂载，服务端权限、路径allowlist、写锁/CAS与审计；禁止中央UI挂载全部Home或提供任意文件/命令执行接口。

## 8. WeKnora远端权威、版本与本地存储

先核对选定WeKnora版本的真实知识/Skill/鉴权/更新/版本API，区别公开源码、Docker镜像和内部版本。可以创建新的本地隔离真实实例，不升级或改旧服务。WeKnora、Hermes、UI的版本锁和兼容测试一起保存。

- 知识通过授权API/MCP检索/读取，UI与Hermes共享同一远端身份规则；记录文档/KB/revision/内容摘要/引用。
- 更新写远端草稿，评测/批准后发布；UI“成功”要由远端读回和下一Run实际消费证明，禁止只写UI目录。
- Skill的说明、脚本、references、依赖必须可从远端正式版本消费。WeKnora自己的Skill系统有API，不代表Hermes自动兼容：实现明确的RemoteSkillProvider/包适配并实际读取、调用。
- 如果现有Hermes原生`skill_view`必须读文件，则下载/校验固定版本到每节点/每Run的只读执行快照或内容寻址缓存；也可实现纯文本远端provider。缓存不成为权威，无需给每节点做一套全量可变知识库。
- 私有Memory/session/workspace仍持久化且隔离，不能由知识库远端化推出“本地不需保存任何状态”。
- 一个Run固定批准的知识/Skill/工具配置组合，远端新版本供下一Run使用；在途Run不随latest漂移。明确版本冲突、并发发布、回退、失效、撤回、缓存资格与断线行为。
- 原生WeKnora修订API不够联合发布时，只补薄的发布manifest协调；内容仍指向远端WeKnora，版本权威只有一个。不要另建本地正式内容库或用可变文档ID冒充不可变release。
- 普通节点身份默认只消费；候选/评测/发布身份单独授权。拒绝未经审核的跨引擎/跨私有scope写回，不自动汇总所有用户Memory为公共知识。
