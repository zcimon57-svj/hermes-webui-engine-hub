## 3. 评审记录方法

在 PR 行内或相应 Issue 中引用 `Xxx` 或目标局部编号，记录：**结论（认可/需修改/缺证据）、理由、建议、所需验证、责任角色**。没有被点名或分派的 GitHub 用户不自动成为评审人；用户自行转发这些链接。

状态分三步记录：设计认可 → 实现与负例验证 → 真实领域/部署验收。建议被写入文档不等于认可；PR 合并不自动关闭任何目标 Issue。当前全部跨目标决策仍待独立评审。
