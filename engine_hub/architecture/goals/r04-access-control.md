## 目标与当前缺口

角色控制操作能力，engine/project/space/owner控制对象范围，两者必须同时满足。当前新Hub已实现基础身份/服务端拒绝与部分scope；现有用户/配置完整管理、项目过滤和执行脚本身份仍有缺口。

## 拟议权限边界

| 身份 | 能力边界 |
|---|---|
| Chat | 在授权空间创建/追问/取消自己的Run，按明确共享权限读取报告 |
| Viewer | 只读已授权会话/报告/批准资产，页面读取不创建会话或Run |
| Admin | 受scope约束的用户/配置/诊断/节点管理；不自动取得业务知识评测/发布权限 |
| 领域评测/审核/发布 | 独立能力与身份，批准绑定候选hash/基线/评测版本，生成者不能自批 |
| worker消费 | 仅该Run上下文、批准资产与必要目标证据；无用户/发布/节点管理密钥 |

身份从可信登录/服务认证得到，不能相信客户端声明角色或任意节点URL。服务调用既校验服务身份也校验传递的业务授权上下文；单个全局服务key不代替最终用户scope。

授权检查贯穿列表、详情、下载/SSE、配置/实例/用户管理、共享、MCP/产物消费及执行动作。缓存、存储路径、前端隐藏、模型分类或汇聚报告不授予额外权限。管理身份不得进入不可信脚本环境。

## 状态与审计

登录/授权变化、共享/撤销、取消、配置变化、评测/批准/发布记录操作者、目标scope、输入/候选/版本及结果。实际内部身份/SSO适配属于F30，当前新Hub不声称已经复用了上游SSO。

撤权/排空影响新派发，活跃Run按明确策略停止/维持，不产生静默越权或结果丢失。审计脱敏，不回显凭据或无权对象内容。

## 必须验收

三独立浏览器身份、API直调、跨engine/project/owner、只读写拒绝、共享撤回、现有用户改权/禁用、配置实例列表与下载/SSE负例。脚本文件系统权限和业务API权限分开验证。
